# nbbang-lab 용어사전 (glossary)

**목적** — 사람이 쓰는 말과 코드 식별자를 잇는다.
nbbang-lab 은 **Claude 아티팩트로 먼저 만든 친구 여행 가계부를 웹 애플리케이션으로 옮기는 프로젝트**라서,
같은 개념이 아티팩트판과 웹앱판에서 다르게 구현될 수 있다. 이 차이가 대화에서 가장 자주 어긋난다.

**사용법**

```bash
grep -n "^### " .claude/glossary.md                   # 전체 목록
grep -n -A6 "^### 덤탱이" .claude/glossary.md          # 특정 용어 상세
grep -n -B2 -A6 "taker" .claude/glossary.md           # 코드 식별자로 역검색
```

- 작업 계획·이슈 논의 시 사전에 있는 용어는 그 표기를 쓴다. 없는 용어를 새로 쓰면 등록을 제안한다.
- 등록·수정은 `/term`. 웹앱 코드가 아직 없어 아래 식별자는 **명세(아티팩트 `trip-data`·작업 계획 문서) 기준**이다 — `(명세)` 표시. 코드가 생기면 실제 경로로 바꾼다.
- 명세 원본: dev-wiki `여행 가계부 작업 계획.md`, 아티팩트 (링크 비공개 — git 밖 private-docs 참고)

> `CLAUDE.md` 와 충돌하면 **`CLAUDE.md`가 우선**한다. 충돌을 발견하면 사용자에게 알린다.

## A. 정산

### N빵 (split)
- **코드 식별자**: `expenses[].split`, `splitEven()` (명세)
- **정의**: 한 지출을 같이 나눌 멤버들끼리 균등 분할하는 것. 나머지 원은 멤버 순서상 앞사람부터 1원씩 더 낸다.
- **별칭**: 더치페이, 같이 나눌 사람
- **혼동 주의**: `split` 은 멤버 id **목록**이지 금액이 아니다. 전원이 아닐 수 있다(혼자 부담·일부 N빵).

### 낸 돈 / 쓴 돈 / 잔액 (paid / owed / bal)
- **코드 식별자**: `paid`, `owed`, `bal` (명세 — 아티팩트 `settle()`)
- **정의**: 낸 돈 = 직접 결제한 합계, 쓴 돈 = N빵으로 나눈 내 몫, 잔액 = 낸 돈 − 쓴 돈. 양수면 받을 돈, 음수면 보낼 돈.
- **혼동 주의**: 100원 단위 정리 **후**의 `owed` 는 `paid − bal` 로 다시 계산된 값이라 N빵 원값과 다르다.

### 덤탱이 쓸 사람 (taker)
- **코드 식별자**: `taker` (명세)
- **정의**: 송금을 100원 단위로 끊고 남는 끝전을 몰아서 떠안는 멤버. 나머지는 모두 유리하게(보낼 돈 내림·받을 돈 올림) 정리된다.
- **별칭**: 덤탱이
- **혼동 주의**: 지정하지 않았거나 없는 멤버면 **가장 많이 받을 사람**이 자동으로 맡는다. 몰빵 게임 당첨자와 다른 개념이다.

### 끝전 (takerCost)
- **코드 식별자**: `takerCost` (명세)
- **정의**: 100원 단위 정리로 덤탱이 쓸 사람이 추가로 부담하는 금액. 화면에 "끝전 +N원".

### 최소 송금 (transfers)
- **코드 식별자**: `transfers` (명세)
- **정의**: 보낼 사람·받을 사람을 금액 큰 순으로 정렬해 greedy 매칭한 송금 목록. 송금 횟수를 줄이는 방식이다.
- **혼동 주의**: 같은 금액을 보내는 두 사람이라도 송금 대상이 다르게 묶일 수 있다 — 버그가 아니다.

## B. 여행 · 지출

### 분류 (category)
- **코드 식별자**: `expenses[].category` (명세)
- **정의**: 지출 분류 고정 7개 — `식비` `카페·간식` `숙소` `교통` `관광·체험` `쇼핑` `기타`. 트리맵 색과 1:1.
- **혼동 주의**: 장보기의 **분류(`shopping[].group`)** 와 이름만 같고 목록이 다르다(`고기` `채소·쌈` …).

### 장보기 (shopping)
- **코드 식별자**: `shopping[]` — `name`·`group`·`done` (명세)
- **정의**: 여행 전에 살 것 체크리스트. 분류(`group`)별로 묶고 담은 것은 아래로 내린다.
- **혼동 주의**: 아티팩트 데이터에 `qty` 가 남아 있는 항목이 있지만 명세상 수량은 입력·표시하지 않는다.

### 여행 티켓
- **코드 식별자**: (없음) — 아티팩트에서는 CSS 클래스 `.ticket`
- **정의**: 화면 맨 위 요약 카드. 여행 이름·날짜·D-day·숙소 주소·예보·총 지출·1인 평균·지출 건수.

### 일차 / D-day (tripBadge)
- **코드 식별자**: `tripBadge()` (명세)
- **정의**: 여행 전 `D-N`, 여행 중 `N일차`, 끝나면 `여행 끝`. 지출 날짜 헤더에도 "N일차 · " 접두어가 붙는다.

## C. 부가 기능

### 몰빵 게임
- **코드 식별자**: (명세) 아티팩트 `game` 상태 — 룰렛 `wheel`·사다리 `ladder`·폭탄 `bomb`·카드 `cards`
- **정의**: N빵 대신 참여자 중 한 명만 당첨시키는 게임. 미션(이번 계산·설거지·고기 굽기·심부름)을 건다.
- **혼동 주의**: 결과를 **저장하지 않는다**. 당첨자 몫으로 지출을 기록하면 그때 일반 지출(`split=[당첨자]`)이 된다.

### 여행 플레이리스트
- **코드 식별자**: (명세) 아티팩트 `SONGS` 배열 `[제목, 가수, 연도, 장르, 분위기]`
- **정의**: 연도·분위기·장르 칩으로 걸러 국내 노래 5곡을 뽑는 기능. 줄 안은 OR, 줄끼리는 AND.

## D. 플랫폼 (아티팩트판 ↔ 웹앱판)

### 저장하고 공유 (rev)
- **코드 식별자**: `rev`, `updatedAt` (명세)
- **정의**: 아티팩트판에서 모아 둔 변경을 한 번에 발행하는 동작. 저장할 때마다 `rev` +1.
- **혼동 주의**: 아티팩트판은 **HTML 전체 재발행**(`artifact.publish`)이고, 웹앱판은 DB 쓰기로 바뀐다. "저장"이 어느 쪽 이야기인지 먼저 분간한다.
  아티팩트의 실데이터는 **라이브 아티팩트 안**에 있다 — 이관할 때는 라이브 버전을 읽어 `trip-data` JSON을 가져온다.
