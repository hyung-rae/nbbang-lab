# 학습 규칙 (review-rules) — nbbang-lab

**이 저장소에서 실제로 반복된 실수와 리뷰 지적**을 규칙으로 누적하는 곳이다.
작업 방식 규칙(W)은 qshop-site 에서 이관했고, 코드 규칙(R)은 비어 있는 상태에서 작업하면서 하나씩 쌓는다.

- **규칙이 쌓이는 방법** — `/rule` 로 직접 넣거나, 같은 지적이 반복될 때 Claude가 먼저 제안한다.
- **작성 형식과 관리 절차** — `.claude/skills/rule/SKILL.md` (= `/rule` 스킬)에 있다.
  **이 파일에는 규칙 항목만 둔다.**
- **W 규칙은 SessionStart 훅이 세션마다 자동으로 불러온다**(`.claude/settings.json`).

**조회**

```bash
grep -n "^### [RW]-[0-9]" .claude/review-rules.md      # 전체 목록
grep -n "^### W-[0-9]" .claude/review-rules.md         # 작업 방식 규칙만
grep -n -A8 "^### W-001" .claude/review-rules.md       # 특정 규칙 상세
```

**두 갈래 — 번호를 섞지 않는다**

| 갈래 | 대상 | 언제 적용 |
|---|---|---|
| **R-NNN** 코드 규칙 | 코드에서 반복된 실수·리뷰 지적 | 해당 경로 작업 전, 코드 리뷰 시 |
| **W-NNN** 작업 방식 규칙 | 협업 방식에 대한 사용자 지시 | 경로와 무관하게 **항상** |

**우선순위 (충돌 시)**

1. `.claude/commands/git/commit.md` — 커밋 형식·절차의 **레포 내 정본**
2. `.claude/rules/CONVENTION.md` — 협업·코드 컨벤션
3. `CLAUDE.md` — 프로젝트 구조·주의사항
4. 이 파일

**여기 있는 규칙이 위 문서와 충돌하면 위 문서가 이긴다.** 충돌을 발견하면 규칙을 임의로 고치지 말고 사용자에게 알린다.
일반론은 넣지 않는다 — 실제로 사고가 났거나 사용자가 직접 지시한 것만 남긴다.

## 작업 방식 규칙 (W-NNN)

<!-- 새 규칙은 이 주석 아래에 순번으로 추가한다. 기존 번호는 재사용하지 않는다. -->

### W-001 · 커밋을 먼저 시작하지 않는다

- **규칙**: `git commit` / `git push` 는 사용자가 **명시적으로 요청할 때만** 시작한다.
  작업 단위가 끝나도 **"커밋할까요?"라고 묻지 않는다.** 변경된 파일을 보고하고 다음 작업으로 넘어간다.
  - **`commit.md` 와 충돌하지 않는다.** 이 규칙은 *커밋을 시작하는 시점*에 대한 것이고,
    `commit.md` 의 "계획 출력 후 확인 없이 실행"은 *요청을 받은 뒤의 진행 방식*이다.
    → **요청받기 전에는 아무것도 안 하고, 요청받은 뒤에는 분할 계획만 출력하고 확인 없이 진행한다.**
- **계기**: qshop-site W-001 이관(2026-08-10 지시) — 작업마다 커밋 여부를 물어 흐름이 끊겼다.
  사용자는 여러 작업을 모아둔 뒤 원하는 시점에 직접 요청하는 방식을 쓴다.
- **적용 시점**: 작업 완료를 보고하는 모든 순간
- **예외**: 사용자가 "커밋해줘"라고 말했을 때. 이땐 묻지 말고 `commit.md` 절차대로 바로 진행한다.

### W-002 · 커밋 분할·형식은 commit.md 를 따른다

- **규칙**: 커밋을 기능·관심사 단위로 쪼개는 절차와 메시지 형식은
  **`.claude/commands/git/commit.md` 가 정본이다.** 이 규칙 파일에 형식을 복사하지 않는다.
  - 커밋 작업을 시작하면 **먼저 `commit.md` 를 읽고** 그 절차(브랜치 가드 포함)를 따른다.
  - gitmoji 컨벤션(`✨ Feat:`, `🐛 Fix:` …)을 쓰고, `Co-Authored-By` 등 트레일러를 붙이지 않는다.
- **계기**: qshop-site W-002 이관(2026-08-10 지시) — 기능이 섞인 커밋은 되돌리기와 리뷰가 어렵다.
- **적용 시점**: 커밋을 실행하는 순간
- **예외**: 사용자가 통합을 명시했을 때. 릴리스 커밋은 `package.json` 한 파일만 담는다.

### W-003 · 커밋 전 코드 리뷰는 물어보고 실행한다

- **규칙**: 커밋 요청을 받으면 **커밋하기 전에 "코드 리뷰를 돌릴까요?"를 묻고, 답을 받아 실행한다.**
  **묻지 않고 임의로 돌리지 않는다** — 리뷰는 수 분이 걸리므로 실행 여부는 사용자가 정한다.

  - **물을 때 수준(effort)을 함께 제안해** 한 번의 답으로 끝나게 한다.
    예: `"커밋 전에 코드 리뷰 돌릴까요? (7파일 +100줄 → medium 권장)"`

  | 수준 | 쓸 때 |
  |---|---|
  | `low` | 문서·주석·상수 값만 바뀐 변경 |
  | **`medium`** | **기본.** 일반적인 기능 추가·버그 수정 |
  | `high` 이상 | 정산 계산·인증/권한·데이터 저장 형식·배포 설정을 건드리거나, 변경이 10파일 또는 500줄을 넘거나, 사용자가 지정했을 때 |

  - 사용자가 **생략을 택하면 되묻지 말고 바로 커밋**한다. 생략했다는 사실만 커밋 보고와 작업 문서에 남긴다.
  - 대상은 커밋할 변경분. `/code-review` 를 쓰고 **R 규칙 대조**를 포함한다.
  - **리뷰 프롬프트를 부풀리지 않는다.** 대상 파일 + 변경 의도 2~3줄 + 최우선 관심사 1개면 된다.
    **스펙·계획 문서를 통째로 대조하라고 시키지 말 것** — 리뷰어마다 그 문서를 전부 읽어 몇 배 느려진다.
    관련 R 규칙은 **번호만 지목**한다.
  - **5분을 넘기면** 진행 상황을 확인해 알리고 선택지를 준다
    (계속 기다림 / 중단하고 직접 리뷰 / 생략). 말없이 계속 기다리지 않는다.
  - 발견된 문제는 **커밋 전에 고친다.** 판단이 필요하거나 범위를 벗어나면 고치지 말고
    **무엇을 발견했는지 보고한 뒤 사용자 판단을 받는다.**
  - 리뷰를 돌렸으면 **결과를 반드시 알린다.** 문제가 없으면 "리뷰 통과"를 한 줄로 보고한다.
- **계기**: qshop-site W-003 이관(2026-08-10 지시, 2026-08-11 보강) — 커밋 후에 발견하면 되돌리는 비용이 크다.
  +100줄 변경에 `high` 를 쓰고 스펙·계획 대조까지 지시해 9분이 지나도 끝나지 않은 일이 있어
  "묻고 실행"과 수준·프롬프트·타임박스 기준이 붙었다.
- **적용 시점**: 커밋 요청 직후, `git commit` 실행 전
- **예외**: 사용자가 "리뷰 없이", "그냥 커밋해" 처럼 **생략을 미리 명시했을 때는 묻지도 않는다.**

### W-004 · 커밋 전 문서 최신화를 확인하고 반영한다

- **규칙**: 커밋 전에 **이번 변경이 문서에 반영돼야 하는지 확인하고, 필요하면 같이 고친다.**

  | 문서 | 이럴 때 갱신 |
  |---|---|
  | 루트 `CLAUDE.md` | 스택·명령어·환경변수·경로 별칭·배포 방식 변경, 새 함정 발견 |
  | 디렉터리별 `CLAUDE.md` | 해당 디렉터리 구조·진입점·절차가 바뀌었을 때 |
  | `.claude/rules/CONVENTION.md` | 협업·코드 컨벤션이 바뀌었을 때 |
  | `.claude/glossary.md` | 새 도메인 용어 등장, 식별자 rename, 혼동되는 쌍 발견 |
  | `.claude/review-rules.md` | 이번 작업에서 규칙으로 남길 지적이 나왔을 때 |
  | dev-wiki `여행 가계부 작업 계획.md` | 기능 명세(무엇을 만드는가) 자체가 바뀌었을 때 |
  | `private-docs/INDEX.md` | 작업 폴더를 만들었거나 문서를 추가했거나 작업 상태가 바뀌었을 때 (요약은 한두 문장) |
  | `private-docs/<작업폴더>/log.md` | 커밋했거나, 판단이 뒤집혔거나, 함정을 발견했을 때 — '지금 상태' 를 함께 갱신 |

  - **문서 수정은 코드 커밋과 섞지 않는다.** `📝 Docs:` 커밋으로 분리한다.
  - **갱신할 게 없다고 판단했으면 그 판단을 한 줄로 말한다.** 조용히 건너뛰지 않는다.
- **계기**: qshop-site W-004 이관(2026-08-10 지시) — 문서가 코드보다 뒤처지면 다음 작업에서 잘못된 전제를 깔게 된다.
- **적용 시점**: 커밋 요청 직후. **리뷰(W-003) 실행 여부와 무관하게 항상 한다.**
- **예외**: 없음. 갱신 불필요라는 결론도 보고 대상이다.

### W-005 · 조사 → 계획 → 확인 → 단계별 진행 → 실측 QA

- **규칙**: 기능 개발·이슈 수정은 다음 순서로 진행한다. **계획 확인 전에 코드부터 고치지 않는다.**
  1. **조사** — 현 상황을 실측으로 파악한다(모든 주장에 `파일:라인` 또는 실행 결과).
     남길 규모면 `/workdoc` 의 `investigation.md` 로.
  2. **계획** — `plan.md` 작성(순서는 체크박스 목록). 순서·건드릴 파일·영향 범위·확인 방법 포함.
  3. **사용자 확인** — 계획을 보고하고 **확인을 받은 뒤에만 착수한다.**
  4. **단계별 작업** — 계획의 단계 단위로 진행하고, 단계가 끝날 때마다
     결과를 보고하고 `plan.md` 체크박스를 채운다(`log.md` 갱신은 W-004 표 기준).
  5. **실측 QA** — 완료 전 `qa.md` 를 만들어 항목별로 실제 확인한다.
     확인하지 않은 항목을 통과로 적지 않는다(⬜ 로 남기고 절차만 적는다).
- **계기**: qshop-site W-005 이관(2026-08-26 지시) — 본인의 표준 진행 방식(조사→계획→확인 후 단계별 작업→실측 QA,
  private-docs 적극 활용)을 세션마다 다시 설명하지 않도록 규칙화.
- **적용 시점**: 기능 개발·이슈 수정 요청을 받은 순간 (단순 질문·자잘한 수정은 해당 없음)
- **예외**: 사용자가 "바로 고쳐줘", "계획 없이 진행해" 처럼 생략을 명시했을 때.
  오타·한 줄 수정처럼 계획이 무의미한 규모일 때 — 이때도 무엇을 바꿨는지는 보고한다.

### W-006 · "private-docs 정리·문서화" = 지식을 git 추적 위치로 승격하고 폴더를 지운다

- **규칙**: 사용자가 private-docs 를 "정리하고 문서화해줘"라고 하면 private-docs 문서를 최신화하는 것이 **아니다.**
  끝난 작업 폴더에서 남길 지식(결정·함정·미해결 결함·미실측 항목·재사용 절차)만 코드로 검증해
  **git 추적 위치 — CLAUDE.md 에 한정하지 않고 glossary·review-rules·스킬·훅 중 맞는 곳**으로 옮기고,
  추적 파일의 private-docs 링크를 없앤 뒤 폴더를 지운다. 절차 정본은 `/workdoc` **H절**, 목적지는 `/documentation` 라우팅 표.
- **계기**: qshop-site W-006 이관(2026-09-11 지시) — "git 으로 관리하는 코드베이스의 claude.md 들에 기록하고 최신화하는 것",
  "CLAUDE.md 뿐 아니라 스킬·훅·용어사전 등 필요한 곳"이라고 정정했다.
- **적용 시점**: private-docs 정리·작업 종료·"문서화" 요청을 받은 순간.
- **예외**: 사용자가 특정 폴더를 남기라고 했을 때. 진행 중인 작업 폴더.

### W-007 · 브라우저 실측은 사용자가 한다 — 요청 전에는 브라우저 도구를 쓰지 않는다

- **규칙**: 화면 확인(브라우저 실측 QA)은 **사용자가 직접 한다.** 사용자가 요청하기 전에는
  브라우저 도구(`mcp__claude-in-chrome__*`, 내장 브라우저 등)로 페이지를 열거나 스크린샷·클릭·스크립트 실행을 하지 않는다.
  - 대신: 테스트·타입·린트·빌드로 확인할 수 있는 것까지만 하고, 화면에서 볼 항목은
    **확인 절차(주소·순서·기대 결과)를 적어 보고**한다(`qa.md` 에는 ⬜ 로 남긴다 — W-005 5단계).
  - 실측에 테스트 데이터가 필요하면 무엇을 어디에 넣을지 제안만 하고, 넣을지는 사용자가 정한다.
- **계기**: 2026-10-07 날씨-음악 작업 — 티켓 예보 줄을 확인하려고 Claude 가 브라우저를 직접 열어 실측하다가 중단됨.
  "브라우저 실측은 내가 직접할게 내가 요청 전까지는 너가 직접하지말아줘".
- **적용 시점**: 화면 변경을 마치고 확인 단계로 넘어가려는 순간, 브라우저 도구를 부르기 직전.
- **예외**: 사용자가 "브라우저로 확인해줘"처럼 명시적으로 요청했을 때 — 그 요청 범위 안에서만.
