# 용어사전 관리

대상 파일: `.claude/glossary.md`

## A. 조회 — 가장 흔한 용도

```bash
grep -n "^### " .claude/glossary.md                  # 전체 목록
grep -n -A7 "^### 덤탱이" .claude/glossary.md         # 특정 용어 상세
grep -n -B3 -A7 "taker" .claude/glossary.md          # 코드 식별자 → 용어 역검색
```

**사람 말 → 코드**, **코드 → 사람 말** 양방향 모두 여기서 먼저 찾는다.
찾은 뒤에는 **혼동 주의** 필드를 반드시 읽는다 — 이 사전의 값어치 대부분이 거기 있다.

사전에 없으면 코드에서 직접 확인하고, 확인에 성공했다면 **C(등록)로 이어간다.**

## B. 대화 중 활용

- 사용자가 쓴 말이 사전에 있으면 **그 표기를 그대로 써서** 답한다.
- 작업 계획·이슈 분석에서 용어가 모호하면 코드 식별자를 괄호로 병기한다.
  예: "덤탱이 쓸 사람(`taker`)이 끝전을 떠안는다"
- 사용자의 말과 코드 식별자가 어긋나면 **지적하지 말고 매핑해서** 진행하되, 사전에 없는 매핑이면 등록을 제안한다.
- **이 프로젝트 특유의 함정**: 원형인 **Claude 아티팩트 버전**과 **웹앱 버전**이 같은 이름의 개념을 다르게 구현할 수 있다
  (예: 저장 = 아티팩트는 HTML 재발행, 웹앱은 DB 쓰기). 어느 버전 이야기인지 먼저 분간한다.

## C. 등록

### 1단계 — 코드로 검증한다 (건너뛰지 않는다)

```bash
git grep -n "<식별자>" -- ':!*.md' | head
```

- 저장소가 git 이 아니면 `grep -rn "<식별자>" . --include='*.ts' --include='*.tsx' --include='*.js' --exclude-dir=node_modules | head`.
  zsh에서는 `--include` 패턴을 **반드시 따옴표로 감싼다.** 안 그러면 glob 오류로 조용히 실패한다.
- 식별자와 경로는 **실제 존재하는 것만** 적는다. 추측 금지.
- 아직 코드가 없고 **명세(아티팩트·작업 계획 문서)에만 있는** 식별자는 출처를 `(명세)` 로 표시한다. 코드가 생기면 실제 경로로 바꾼다.
- 대응 식별자가 없는 대화용 용어면 `**코드 식별자**: (없음)` 이라고 **명시**한다.

### 2단계 — 중복·소속 확인

```bash
grep -n "^### " .claude/glossary.md
```

- 이미 있으면 새로 만들지 말고 **기존 항목을 보강**한다.
- 이름이 바뀐 경우도 새 항목이 아니라 **기존 항목의 별칭에 옛 이름을 남긴다.**
- 분류 중 맞는 곳에 넣는다. 맞는 분류가 없으면 새로 만들되, 분류가 10개를 넘으면 통합을 검토해 제안한다.

### 3단계 — 작성

```markdown
### 용어 (code identifier)
- **코드 식별자**: 실제 코드에 있는 이름. 없으면 `(없음)` 이라고 명시한다
- **정의**: 한두 문장
- **별칭**: 다른 말 (없으면 생략)
- **관련 파일**: 실존하는 경로
- **혼동 주의**: 비슷하지만 다른 것 (없으면 생략)
```

**혼동 주의는 적극적으로 채운다.** 아래면 반드시 쓴다:

- 이름이 비슷한 다른 것이 있다
- 같은 단어가 다른 층위에서 쓰인다
- 아티팩트 버전과 웹앱 버전에서 같은 이름이 다르게 동작한다
- 실수하면 조용히 깨진다 (예: 금액을 실수로 계산해 1원 오차가 난다)

**원칙**

- **검증한 것만 적는다.** 추측 금지.
- **`glossary.md` 에는 용어 항목만 넣는다.** 형식 예시나 관리 설명을 그 파일에 쓰지 않는다 —
  `grep "^### "` 목록이 예시까지 잡아 인덱스가 오염된다. 그래서 이 설명이 여기(스킬)에 있다.

### 4단계 — 보고

추가한 항목 전문을 보여준다. **임의로 커밋하지 않는다**(W-001).

## D. 수정 / 폐기

- **수정**: 코드가 바뀌어 식별자·경로가 달라졌다면 다시 grep으로 검증한 뒤 갱신한다.
- **폐기**: 삭제하지 말고 제목 뒤에 `(폐기: 사유)`를 붙인다.
- **이름이 바뀐 경우**: 새 항목을 만들지 말고 기존 항목의 별칭에 옛 이름을 남긴다.
- **정합성 점검**(요청 시): 관련 파일 칸의 경로가 실제로 있는지 확인한다.
  ```bash
  grep -oE '`[A-Za-z0-9_./-]+/[A-Za-z0-9_.-]+\.[a-z]+`' .claude/glossary.md | tr -d '`' | sort -u \
    | while read -r p; do [ -e "$p" ] || echo "없는 경로: $p"; done
  ```

## 자동 제안으로 들어온 경우

절차는 같되 **질문을 최소화한다.** 검증 → 항목 작성 → 보여주고 확인, 까지만 한다.
