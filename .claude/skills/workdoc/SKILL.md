# 작업 문서 관리 (private-docs)

대상: `private-docs/` — **git에 올라가지 않는다**(`.gitignore` 의 `private-docs/*`).
git 히스토리가 없으므로 **`private-docs/INDEX.md` 의 작업 목록이 유일한 색인**이고,
**각 폴더의 `log.md` 가 그 작업의 유일한 진행 기록**이다. 갱신을 빠뜨리면 기록이 사라진다.

## 구조

```
private-docs/
├── INDEX.md                      ← 색인. 작업 한 줄씩 + 문서 링크 (길라잡이 아님)
└── YYYY-MM-DD-<작업이름>/          ← 작업 단위 폴더
   ├── note.md            사용자 → Claude 전달 메모 (사용자가 쓴다)
   ├── investigation.md   조사 — 원인 조사, 코드 조사 결과
   ├── plan.md            계획 — 수립한 작업 계획
   ├── spec.md            스펙 — 개발할 기능 명세
   ├── qa.md              QA — 확인할 항목, 테스트 결과
   ├── log.md             로그 — 이 작업의 진행 기록 (시간순)
   └── scripts/           (선택) 재실행에 필요한 실행 파일
```

- **6종을 다 만들 필요는 없다.** 필요한 것만 만든다.
- 파일명은 위 6개로 **고정**한다. 바꾸면 조회 명령과 INDEX 링크가 깨진다.
- **`scripts/` 는 허용된 유일한 하위 폴더다** (2026-09-01 추가). 아래 G절.

### 문서 성격

| 문서 | 누가 쓰나 | 무엇을 담나 |
|---|---|---|
| `note.md` | **사용자** | Claude에게 전달할 내용. 기능 아이디어, 추가 요구, 참고사항 |
| `investigation.md` | Claude | 원인·코드 조사 결과. **근거(파일:라인, 명령 출력) 필수** |
| `plan.md` | Claude | 무엇을 어떤 순서로. 영향 범위(화면·데이터·권한)와 확인 방법 포함 |
| `spec.md` | Claude | 기능 동작 명세. 입력·출력·예외·비적용 범위 |
| `qa.md` | Claude | 확인 항목 체크리스트와 실제 결과 |
| `log.md` | Claude | 언제 무엇을 했고 무엇이 바뀌었나. 커밋 해시·번복된 판단·함정 |

**`note.md`는 방향이 반대다.** 작업 시작 시 있으면 **가장 먼저 읽는다.**

**`INDEX.md` 와 `log.md` 의 경계** — INDEX 는 색인이다. 요약은 **한두 문장**을 넘지 않는다.
진행 기록·커밋 해시·경고는 전부 `log.md` 로 보내고 INDEX 에는 링크만 둔다.
(실제로 INDEX 요약 칸이 2,000자짜리 로그가 되어 표를 읽을 수 없게 된 적이 있다.)

## 항상 먼저

```bash
cat private-docs/INDEX.md          # 기존 작업 확인
ls private-docs                    # 작업 폴더 목록
date +%F                           # 폴더명에 쓸 오늘 날짜 (추측하지 말 것)
```

## A. 작업 시작 — 폴더 만들기

폴더명 `YYYY-MM-DD-<작업이름>` (날짜 = 작업 시작일, 이슈 번호가 있으면 이름에 포함).

```bash
mkdir -p "private-docs/$(date +%F)-<작업이름>"
```

- **기존 작업의 연장이면 새 폴더를 만들지 말고** 기존 폴더에 문서를 추가한다.
- 폴더를 만들었으면 **그 즉시 `INDEX.md` 표에 한 줄 추가**한다 (D절).

## B. `note.md` — 사용자가 쓰는 문서

**방향이 반대다.** 사용자가 Claude에게 전달할 내용을 적어두는 곳이다.

- **작업을 시작할 때 해당 폴더에 `note.md`가 있으면 가장 먼저 읽는다.**
- 사용자가 명시적으로 요청하지 않는 한 **Claude가 `note.md`를 수정하지 않는다.**
- 사용자가 "노트에 적어둘게"라고 하면 빈 `note.md`만 만들어 준다.

## C. 문서 작성

파일명은 **고정**이다: `note.md` / `investigation.md` / `plan.md` / `spec.md` / `qa.md` / `log.md`.
필요한 것만 만든다 — 6종을 다 채우려 하지 말 것.

> **아래 양식은 초안이다.** 실제 작업에서 부족한 점이 드러나면 고쳐 나간다 (F절).
> 양식에 없는 항목이 필요하면 **그 자리에서 추가해 쓰고**, 반복되면 양식 개정을 제안한다.
> 양식을 지키느라 필요한 내용을 빼는 일은 없어야 한다.

### investigation.md — 조사

**근거 없는 문장을 쓰지 않는다.** 모든 주장에 `파일:라인` 또는 명령 출력을 붙인다.

```markdown
# 조사: <제목>

## 질문
무엇을 밝히려 했는가.

## 결론
확인된 사실. 확실한 것과 추정을 **분리해서** 쓴다.

## 근거
- `src/lib/settle.ts:42` — 100원 단위 정리 후 끝전을 taker 에게 몰아준다
- 실행: `git grep -n "taker"` → 5개 파일

## 확인하지 못한 것
조사 범위 밖이거나 확인에 실패한 것. **비워두지 말 것** — 다음 사람이 여기서 이어받는다.
```

### plan.md — 계획

```markdown
# 계획: <제목>

## 목표
무엇이 끝나면 완료인가.

## 순서
- [ ] 1. …  (파일 경로까지 구체적으로)
- [ ] 2. …

<!-- 단계가 끝날 때마다 체크하고 결과를 보고한다(W-005).
     계획이 바뀌면 항목을 지우지 말고 ~~취소선~~ + 이유 한 줄. -->

## 영향 범위
건드리는 경로와 함께 깨질 수 있는 곳.
**권한(소유자·멤버·비로그인 방문자)별 차이와 모바일 화면**을 반드시 적는다.

## 확인 방법
판정 절차. 무엇을 실행해서 어떤 결과가 나오면 통과인지 적는다.
정산 계산을 건드렸으면 금액 합계가 1원 단위까지 맞는지 확인한다.

## 하지 않을 것
범위 밖으로 두는 것.
```

### spec.md — 스펙

```markdown
# 스펙: <기능명>

## 동작
방문자 관점에서 무엇이 어떻게 되는가.

## 입력 / 출력
데이터 형태. 저장된 여행 데이터를 읽는 경우 **어느 필드에 의존하는지** 명시한다.

## 예외 / 경계
빈 값, 최대치, 실패 시 동작.

## 적용 범위
권한(소유자·멤버·비로그인 방문자), 모바일/데스크톱, 여행 전·중·후 같은 상태 조건.

## 비적용 범위
이 스펙이 다루지 않는 것.
```

### qa.md — QA

```markdown
# QA: <제목>

| # | 확인 항목 | 절차 | 결과 | 비고 |
|---|---|---|---|---|
| 1 | … | … | ⬜ 미확인 / ✅ 통과 / ❌ 실패 | |

## 실패 항목
재현 절차와 증상.
```

**결과를 정직하게 적는다.** 확인하지 않은 항목을 통과로 적지 않는다.

### log.md — 진행 기록

**언제 만드나**: 진행 기록이 INDEX 요약 한두 문장에 안 담기기 시작할 때.
착수와 동시에 만들 필요는 없다 — 다른 문서와 같이 **필요해지면** 만든다.

```markdown
# 로그: <작업 이름>

관련 문서: [investigation.md](investigation.md) · [plan.md](plan.md)

<!-- 최신이 위. 날짜별 블록으로 추가한다. -->

## 지금 상태

이어받는 사람이 **가장 먼저 읽을 한 문단.** 브랜치·커밋 해시·다음에 할 일·미확인 항목.

---

## YYYY-MM-DD — <무엇을 했나>

- 한 일과 그 결과
- 바꾼 파일
- ⚠️ 함정 / **번복된 판단** (틀린 초안을 지우지 말고 왜 틀렸는지 남긴다)
```

- **'지금 상태' 는 덮어쓴다.** 그 아래 날짜 블록은 **지우지 않고 쌓는다.**
- **판단이 뒤집혔으면 옛 판단을 지우지 말 것.** "이 판단은 틀렸다 — 이유" 로 남긴다.
  같은 함정을 다시 밟는 것을 막는 게 로그의 가장 큰 값이다.
- 커밋했으면 **해시를 적는다.** 다른 저장소에 짝 커밋이 있으면 같이 적는다.

## D. INDEX.md 갱신 — 건너뛰지 말 것

git 히스토리가 없으므로 이 표가 사라지면 색인이 사라진다.
**폴더를 만들 때 / 문서를 추가할 때 / 상태가 바뀔 때** 매번 갱신한다.

| 시작일 | 작업 | 상태 | 문서 | 요약 |
|---|---|---|---|---|
| 2026-10-06 | [웹앱-초기-세팅](2026-10-06-웹앱-초기-세팅/) | 진행중 | [조사](…/investigation.md) · [계획](…/plan.md) · [로그](…/log.md) | **착수 전.** 아티팩트 가계부를 웹앱으로 옮긴다. |

- **문서** 칸에는 실제로 존재하는 것만, **파일 링크로** 적는다.
  `scripts/` 가 있으면 폴더 링크로 한 칸 더 건다(`[스크립트](…/scripts/)`) — G절.
- **상태**: `진행중` · `완료` · `보류` · `폐기` **4종만 쓴다.**
  "커밋됨(QA 대기)" 같은 세부는 상태 칸이 아니라 요약 첫머리에 굵게 적는다.
  작업이 끝나면 **`완료`로 바꾸는 것까지가 작업이다.**
- **요약은 한두 문장.** 넘치면 `log.md` 로 보낸다 — INDEX 를 로그로 만들지 말 것.
- 폐기된 작업도 줄을 지우지 않는다. 상태만 바꾸고 요약에 사유를 남긴다.
- 짝 문서가 다른 곳(dev-wiki 등)에 있으면 INDEX 의 **'짝 문서' 표**에 한 줄 남긴다.
- 이 디렉토리 **구조 자체를 바꿨으면** INDEX 의 **'구조 변경 이력'** 에 옛 경로 → 새 경로 매핑을 남긴다.

## E. 조회

```bash
ls private-docs                                          # 작업 목록
sed -n '/## 작업 목록/,/^## /p' private-docs/INDEX.md      # 색인 표
cat private-docs/<작업폴더>/log.md                         # 그 작업의 진행 기록
grep -rn "<키워드>" private-docs --include='*.md'          # 전체 검색
```

기존 작업을 이어받을 때는 **`log.md`(지금 상태) → `note.md` → `investigation.md` → `plan.md` 순으로 읽는다.**

## F. 양식은 쓰면서 다듬는다

C절 양식은 **완성본이 아니라 출발점**이다.

| 신호 | 어떻게 고치나 |
|---|---|
| 양식에 없는 항목을 **매번 덧붙여 쓰고 있다** | 정식 필드로 추가 |
| 어떤 필드를 **매번 비워둔다** | 삭제하거나 `(선택)` 표시 |
| 같은 누락·실수가 **문서에서 반복된다** | 해당 필드에 경고 문구를 박아 넣는다 |
| 사용자가 문서를 읽고 **같은 것을 반복해서 되묻는다** | 되묻는 내용이 필드로 빠져 있다는 뜻 |
| **INDEX 요약 칸이 길어진다** | 그 작업의 `log.md` 로 옮기고 INDEX 에는 링크만 남긴다 |

**절차**: 한 줄로 제안 → 승인 → 이 파일 수정. **승인 없이 양식을 고치지 않는다.**
변경 이력은 git이 기록한다(`.claude/` 는 추적 대상) — 별도 changelog를 만들지 말 것.

**제동**: 필드를 늘리기만 하면 아무도 안 채우는 서식이 된다. 추가 전에 확인한다 —
이 필드를 비워둔 문서가 **실제로 문제를 일으켰는가?** 기존 필드를 넓혀 담을 수 있는가?
한 양식의 필드가 7개를 넘으면 통합을 검토해 제안한다.

## G. `scripts/` — 절차를 재실행 가능하게 남길 때

문서가 **절차**이고 그 절차에 실행 파일이 딸려 있으면, 파일을 작업 폴더의 `scripts/` 에 함께 둔다.

**왜 두나** — `private-docs/` 는 git 대상이 아니다. 스크립트를 임시 디렉토리에만 두면
세션이 끝나는 순간 사라지고, 남은 문서는 "이런 걸 했다"는 회고가 될 뿐 다시 돌릴 수 없다.
실제로 절차 문서만 남기고 스크립트를 잃어 처음부터 다시 짠 적이 있다.

**규칙**

- 폴더 이름은 `scripts/` 로 **고정**한다. 하위 폴더는 여기 하나뿐이다.
- **재실행에 필요한 것만** 넣는다 — 실행 파일, 그 입력이 되는 고정 데이터(`trip-data.json` 등).
- **폐기한 시도는 넣지 않는다.** 안 되는 방법을 남기면 다음 사람이 그걸 먼저 돌려 본다.
  왜 폐기했는지는 `log.md` 의 '번복된 판단' 에 적는다.
- **결과물은 손으로 챙겨 넣지 않는다.** 스크립트를 돌리면 그 자리에 생기는 것(이미지·HTML)은
  생겨도 그만이고, 없어도 스크립트로 다시 만들면 된다.
- 스크립트는 **자기 위치 기준으로 경로를 잡는다**(`os.path.dirname(os.path.abspath(__file__))`).
  어디서 부르든 돌아야 한다.
- 넣었으면 **`spec.md`(또는 해당 문서)에 실행 순서를 적고**, INDEX 문서 칸에 `[스크립트](…/scripts/)` 를 건다.

**넣지 않아도 되는 경우** — 절차가 명령 두어 줄이면 문서 본문에 적는 편이 낫다.
`scripts/` 는 "문서만 봐서는 다시 못 돌린다" 싶을 때 만든다.

## H. 작업 종료 — 지식을 승격하고 폴더를 지운다

`private-docs/` 는 git 밖이라 **남겨 둬도 팀 지식이 되지 않는다.** 작업이 끝나(배포까지 확인) 폴더를 정리할 때는
**지우기 전에 남길 지식을 git 추적 위치로 옮긴다.** 사용자가 "private-docs 정리하고 문서화해줘"라고 하면 이 절이다
— private-docs 문서를 최신화하라는 뜻이 아니다.

1. **끝났는지 확인** — 커밋이 `origin/main` 에 있는지 `git branch -r --contains <해시>` 로 본다.
   INDEX 의 "미커밋·미push" 표기는 낡았을 수 있다.
2. **후보 추출** — 폴더별로 결정·함정·근본 원인·미해결 결함·미실측 항목·재사용 절차를 뽑고,
   **이미 추적 문서·코드 주석에 있는지 대조**한다. 폴더가 크면 폴더별 읽기 전용 에이전트로 병렬 추출한다.
3. **코드로 검증** — 후보마다 현재 코드 `파일:라인` 으로 아직 참인지 확인한다. 코드와 어긋나는 후보는 버린다.
4. **목적지 라우팅** — `/documentation` 라우팅 표를 따른다. **CLAUDE.md 만이 아니다**: 용어는 `glossary.md`,
   작업 방식 지시는 `review-rules.md` W, 반복 절차는 해당 스킬, 기계적으로 강제할 수 있는 것은 훅·eslint 로.
   진행 기록·커밋 경위·일정 같은 **이력은 옮기지 않는다**(git 몫).
5. **추적 파일의 private-docs 링크 제거** — `git grep -n "private-docs/20[0-9][0-9]-" -- ':!private-docs'` 가 0 이어야 한다
   (다른 레포의 private-docs 를 가리키는 것은 예외).
6. **폴더 삭제 + INDEX 갱신** — 작업 표에서 행을 빼고 '구조 변경 이력' 에 무엇을 지웠고 지식이 어디로 갔는지 남긴다.
   되돌릴 수 없으므로 **사용자 지시가 있을 때만** 지운다. `rm` 이 권한으로 막히면 사용자에게 `! rm -rf …` 실행을 요청한다.

## 주의

- 문서는 **작업의 부산물이지 목적이 아니다.** 간단한 수정에 문서를 만들지 말 것.
- 문서를 **옮기거나 이름을 바꿀 때는 상호 참조를 함께 갱신한다.**
  실제로 이관 시 6건의 참조가 깨진 적이 있다:
  `grep -rn "private-docs/.*\.md" private-docs` 로 확인한다.
- 저장소 코드 규칙(`CLAUDE.md`, `.claude/review-rules.md`)이 문서보다 우선한다.
- 문서에 시크릿·토큰 값을 적지 않는다. git에 안 올라간다고 해도 마찬가지다.
