# 학습 규칙 추가 / 관리

대상 파일: `.claude/review-rules.md`

## 먼저 할 일

```bash
cat .claude/review-rules.md
```

기존 규칙과 번호 체계를 반드시 먼저 읽는다. 읽지 않고 추가하면 중복이 쌓인다.

## 규칙 갈래 — 먼저 어느 쪽인지 정한다

| 갈래 | 대상 | 필수 필드 |
|---|---|---|
| **R-NNN** 코드 규칙 | 코드에서 반복된 실수·리뷰 지적 | 규칙 / 계기 / **확인법** / **범위** |
| **W-NNN** 작업 방식 규칙 | 협업 방식에 대한 사용자 지시 | 규칙 / 계기 / **적용 시점** / 예외 |

판단 기준: **코드를 보고 위반을 찾을 수 있으면 R, 내 행동에 대한 지시면 W.**
번호는 갈래별로 따로 매기고 섞지 않는다.

## A. 규칙 추가

### 1단계 — 무엇을 규칙으로 만들지 확정

사용자가 `/rule` 만 입력했다면 **직전 대화 맥락에서** 지적 내용을 찾아 쓴다.
근거가 불충분하면 지어내지 않는다. 특히 **계기(언제/어디서/무슨 증상)** 는 추측하지 말고,
모르면 사용자에게 묻거나 `계기: (미기록)` 으로 둔다.

### 2단계 — 상위 문서와 중복인지 확인

이 저장소에는 **이미 정본 문서가 있다.** 아래에 있는 내용이면 **추가하지 말고 어디 있는지 알려준다**:

| 문서 | 담당 |
|---|---|
| `.claude/commands/git/commit.md` | 커밋 형식·분할 절차·브랜치 가드 (**레포 내 정본**) |
| `.claude/rules/CONVENTION.md` | 협업·코드 컨벤션 (규범) |
| `CLAUDE.md` (루트 + 디렉터리별) | 구조·명령어·함정 (설명) |
| `.claude/glossary.md` | 용어 ↔ 코드 식별자 |

그 외에 추가하지 말아야 할 것:

- 이미 `review-rules.md` 에 있는 내용 → 기존 항목 번호를 알려주고 필요하면 그 항목을 보강한다.
- 이 저장소와 무관한 일반 코딩 원칙, 일회성 취향, 그 대화에서만 유효한 요청.
- **확인법을 쓸 수 없는 것**(R 규칙에 한함) → 리뷰에서 대조가 불가능하다.
  훅이나 린트 룰로 강제 가능한지 먼저 검토해 제안한다. **W 규칙에는 이 기준을 적용하지 않는다.**

### 3단계 — 항목 작성 후 추가

해당 갈래의 틀을 그대로 따른다. 번호는 **같은 갈래** 마지막 규칙 + 1.
해당 갈래 목록이 비어 있으면 `_아직 등록된 ... 규칙이 없다._` 줄을 **지우고** 첫 항목을 넣는다.

**코드 규칙 (R-NNN)**

```markdown
### R-001 · 한 줄 제목

- **규칙**: 무엇을 해야/하지 말아야 하는지. 검증 가능한 문장으로 쓴다.
- **계기**: 언제 어디서 무슨 문제가 있었는지 (날짜 / PR·이슈 번호 / 증상).
- **확인법**: 리뷰할 때 이 규칙 위반을 어떻게 찾는지 (grep 명령, 확인할 파일, 재현 절차).
- **범위**: 적용되는 경로 glob. 저장소 전체면 `**`.
```

**작업 방식 규칙 (W-NNN)** — 코드가 아니라 협업 방식이라 `확인법`·`범위` 대신 다른 필드를 쓴다.

```markdown
### W-001 · 한 줄 제목

- **규칙**: 어떻게 행동해야 하는지. "하지 말 것"이면 대신 무엇을 할지까지 쓴다.
- **계기**: 어떤 상황에서 이 지시가 나왔는지 (날짜 / 무엇이 불편했는지).
- **적용 시점**: 이 규칙을 떠올려야 하는 순간.
- **예외**: 적용하지 않는 경우 (없으면 생략).
```

### 필드 작성 기준

- **규칙**은 검증 가능한 문장으로. "조심한다" 금지.
- **확인법**은 실제로 동작하는 grep/명령. **쓰기 전에 한 번 실행해** 결과가 나오는지 확인한다.
  zsh에서는 `--include` 패턴을 반드시 따옴표로 감싼다 (`--include='*.ts'`).
- **범위**는 실제 존재하는 경로 glob.
- **제목에 `R-`/`W-` 외의 접두사를 쓰지 않는다.** 조회 명령과 SessionStart 훅이 이 형식에 의존한다.

### 4단계 — 보고

추가한 항목 전문을 보여준다. **임의로 커밋하지 않는다**(W-001).
커밋을 요청받으면 `commit.md` 절차를 따르고 `📝 Docs:` 타입을 쓴다.

## B. 규칙 조회

```bash
grep -n "^### [RW]-[0-9]" .claude/review-rules.md   # 전체 목록
grep -n "^### W-[0-9]" .claude/review-rules.md      # 작업 방식 규칙만
grep -n -A8 "^### R-007" .claude/review-rules.md    # 특정 규칙 상세
```

`[0-9]` 를 빼면 다른 문서의 형식 예시까지 잡힐 수 있다. 패턴을 줄이지 말 것.

## C. 규칙 수정 / 폐기

- **수정**: 해당 항목만 고친다. 번호는 유지한다.
- **폐기**: 삭제하지 말고 제목 뒤에 `(폐기: 사유)`를 붙인다. 왜 있었는지가 정보다.
- **병합**: 같은 원인의 규칙이 3개 이상이면 상위 규칙으로 묶는 것을 제안한다 — 실행은 승인 후.
- **승격**: 기계적으로 검사 가능한 규칙은 훅이나 린트 룰로 옮기자고 제안한다.

## 자동 제안으로 들어온 경우

사용자가 "예"라고 답해 들어왔다면 절차는 같되 **질문을 최소화한다.**
계기가 불명확하면 묻지 말고 `계기: (미기록)`으로 두고, 나머지를 채워 항목을 보여준 뒤 확인받는다.
