# /documentation — 지식 남기기 (라우팅)

작업이 끝난 뒤 "다음 세션의 Claude가 다시 설명받지 않아도 되도록" 이번에 알게 된 것을 **맞는 곳 한 군데**에 남긴다.

**핵심 원칙: 정본 1곳 + 필요하면 링크.** 같은 사실을 두 곳에 쓰지 않는다.
개인 프로젝트지만 지식이 놓일 곳은 네 갈래다 — **레포(git 추적)**, **dev-wiki 보관함**, **private-docs(로컬 작업 기록)**, **auto-memory**.
어디에 쓸지가 실제 문제다 — 그 결정이 이 스킬의 전부다.

## 1단계 — 후보 수집

인자가 있으면(`/documentation <주제>`) 그 주제만 처리한다. 없으면 이번 세션에서 아래에 해당하는 것을 추린다.

- **남길 것**: 결정(스택·구조·데이터 모델 선택과 그 이유) / 규칙·컨벤션·제약 / 반복된 사용자 지시·선호 / **코드만 봐서는 안 드러나는 의도** / 버그의 근본 원인과 재발 방지 조건 / 데이터 구조의 동작 규칙 / **조사·디버깅으로 얻은 비자명한 결론** / **명세(아티팩트판)와 달라진 점** — 채팅 기록으로 증발시키지 않는다.
- **남기지 않을 것**: git이 이미 기록하는 것(변경 이력 → 커밋 본문 몫) / 코드에서 자명한 것 / 이번 대화에만 유효한 일회성 맥락 / 일시 상태("빌드 통과함") / 이 저장소와 무관한 일반 코딩 원칙(→ 필요하면 dev-wiki 학습 노트로).

후보가 하나도 없으면 **"남길 지식 없음"** 한 줄만 밝히고 끝낸다. 억지로 만들지 않는다.

## 2단계 — 라우팅 (정보 유형 → 정본 위치)

| 정보 유형 | 정본 위치 | 경유 스킬 · 비고 |
|---|---|---|
| 특정 디렉터리에 국한된 구조·데이터 shape·함정 | **해당 디렉터리 `CLAUDE.md`** | 그 폴더 작업 시 자동 로드됨 — 코드가 생긴 뒤의 기본 목적지 |
| 프로젝트 전역 구조·스택·명령어·함정 | 루트 `CLAUDE.md` | **최소·신중**, 사용자 승인 후 |
| 코드에서 반복된 실수·리뷰 지적 | `.claude/review-rules.md` **R-NNN** | `/rule` — 승인 후. **확인법을 쓸 수 없으면 등록하지 않는다** |
| 내 작업 방식에 대한 사용자 지시 | `.claude/review-rules.md` **W-NNN** | `/rule` — 승인 후 |
| 규범("이렇게 써라") — 코드·커밋 컨벤션 | `.claude/rules/CONVENTION.md` | 승인 후. 설명이 아니라 **규범만** |
| 커밋 형식·분할 절차·브랜치 가드 | `.claude/commands/git/commit.md` | 레포 내 정본 |
| 반복되는 작업 절차(무엇을 어떤 순서로) | 해당 **스킬** `.claude/skills/<이름>/SKILL.md` | 기존 스킬의 절을 보강한다. 새 스킬은 절차가 독립적일 때만 |
| 사람이 기억하지 않아도 기계가 막을 수 있는 규칙 | **훅**(`.claude/settings.json` `hooks`) 또는 린트 룰·테스트 | 강제 가능하면 문서보다 우선 검토. 정산 금액 규칙은 **테스트로 고정**하는 것이 가장 강한 문서다 |
| 사람 말 ↔ 코드 식별자 매핑, 아티팩트판과 이름 충돌 | `.claude/glossary.md` | `/term` — **등록 전 코드로 검증**. 코드가 생기면 `(명세)` 표시를 실제 경로로 바꾼다 |
| **제품 명세(무엇을 만드는가)와 그 변경** | dev-wiki `여행 가계부 작업 계획.md` | 웹앱에서 기능·규칙이 바뀌면 그 문서의 해당 절을 갱신한다. 레포에는 복사하지 않고 링크만 |
| 이 프로젝트 밖에서도 쓸 일반 개발 지식·학습 노트 | dev-wiki 보관함 | `/save-notes` — 레포 문서에 쓰지 않는다 |
| 작업 단위 조사·계획·스펙·QA·진행 기록 | `private-docs/YYYY-MM-DD-<작업>/` | `/workdoc` — **INDEX.md 등재 + log.md 1줄 필수**. git 대상 아님 |
| 사용자 선호·환경 특이사항·미확정 가설 등 레포에 부적합한 것 | **auto-memory** (`~/.claude/projects/-Users-hyung-rae-Desktop-nbbang-lab/memory/`) | frontmatter + `MEMORY.md` 인덱스 규칙에 따라 |
| 변경 이력·왜 이렇게 고쳤는지 | **문서화하지 않는다** | 커밋 본문 몫 |

**헷갈리는 경계 4개**

- `CLAUDE.md` ↔ `review-rules.md` — **"이렇게 되어 있다"는 CLAUDE.md, "이 실수가 반복됐다"는 review-rules.** 구조 설명을 규칙으로 등록하지 않는다.
- `CONVENTION.md` ↔ `CLAUDE.md` — **규범은 CONVENTION, 설명은 CLAUDE.md.** (CONVENTION.md 머리말 참조)
- 레포 ↔ dev-wiki — **"어떻게 만들었나"(구현·구조·함정)는 레포, "무엇을 만드나"(기능 명세)는 dev-wiki 계획 문서, "다른 프로젝트에도 쓸 배움"은 dev-wiki 노트.**
  명세 문서에 구현 세부(파일 경로·함수명)를 쓰지 않고, 레포 문서에 기능 명세를 복사하지 않는다.
- `private-docs/` ↔ 레포 문서 — private-docs는 **git에 안 올라간다.** 상주가 보장되지 않으므로 **CLAUDE.md 같은 레포 문서에서 링크하지 않는다** — 재사용 가치가 생기면 내용을 이 표의 목적지로 승격한다. 작업 폴더를 정리할 때의 절차는 `/workdoc` H절.

## 3단계 — 중복 검사 (저장 전 필수)

```bash
grep -rn "<핵심 키워드>" --include='CLAUDE.md' --exclude-dir=node_modules . ; grep -rn "<핵심 키워드>" .claude/*.md .claude/rules/
grep -n "<핵심 키워드>" "/Users/hyung-rae/Desktop/dev-wiki/여행 가계부 작업 계획.md"   # 명세에 이미 있는지
```

- 이미 있으면 → **그 문서를 갱신**한다(신규 파일 금지).
- 다른 위치에 정본이 있으면 → 정본은 그대로 두고 **링크만** 건다.
- 기존 내용과 **모순**되면 조용히 덮어쓰지 말고, 코드로 실측해 어느 쪽이 맞는지 판정한 뒤 정정한다. 판단이 안 서면 해당 위치에 `> ⚠️ 상충:` 한 줄을 남기고 사용자에게 묻는다.
  명세(dev-wiki)와 구현이 어긋나면 **어느 쪽이 의도인지 사용자에게 묻는다** — 구현에 맞춰 명세를 조용히 고치지 않는다.

## 4단계 — 저장 1회의 정의 (문서 하나 쓰고 끝이 아니다)

지식 하나를 저장하는 작업은 다음을 모두 마쳐야 완료다.

1. **정본 저장** — 라우팅 표의 목적지 1곳에 작성/갱신.
2. **교차 갱신** — 같은 주제를 다루는 기존 문서 1~2곳에 한 줄 요지 + 링크를 반영한다(새 지식이 고아가 되지 않게).
3. **모순 표시** — 3단계에서 발견한 충돌 처리.
4. **인덱스·로그** — 목적지가 `private-docs/`면 `INDEX.md` 등재 + 해당 폴더 `log.md` 1줄. auto-memory면 `MEMORY.md`에 한 줄 포인터. dev-wiki 명세를 고쳤으면 그 문서의 `작업 순서` 체크리스트도 맞춘다.

## 5단계 — 적용

1. **분배 계획 표를 먼저 출력한다**: `항목 | 목적지 | 신규/갱신 | 한 줄 요지`
2. 적용. 단 **루트 `CLAUDE.md` · `.claude/rules/` · `.claude/review-rules.md` · `.claude/glossary.md` · dev-wiki 명세 문서는 사용자 승인 후에만** 수정한다(디렉터리별 `CLAUDE.md`와 `private-docs/`는 승인 없이 진행).
3. **커밋은 이 스킬이 하지 않는다** (W-001). 코드 변경에 딸린 문서 갱신이면 같은 브랜치에 남겨두고 보고만 한다. dev-wiki 는 별도 저장소라 그쪽 커밋도 하지 않는다.

## CLAUDE.md 작성 규칙 (증강 시 준수)

- **한국어**, 기존 톤(표·불릿·짧은 코드블록)을 유지한다.
- **현재 상태만** 기술한다 — 변경 로그·히스토리 축적 금지(낡음의 원인). 히스토리는 `log.md`와 커밋 몫이다.
- 규칙에는 근거 앵커(`파일:라인` 또는 정본 문서 링크)를 단다. **추측 금지** — 확인 못 한 것은 "(확인 필요)"로 남긴다.
- 큰 JSON·긴 설명은 인라인 금지 → 대표 shape 축약. 문서는 스캔 가능한 길이를 유지한다.
- `private-docs/**`를 레포 문서에서 링크하지 않는다.
